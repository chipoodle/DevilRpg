Source reviewed:

- Global A* stores `actionPos` in `NavGraphSearch.Edge/Step` and reconstructs it into `NavRoute.Node`. For BUILD, the graph state is the resulting feet cell and `actionPos` is the placement cell.
- `NavExecutor.elegirObjetivoLocal` scans global route nodes, selects BUILD as a local waypoint, and retains `objetivoTransicionLocal=BUILD` and `objetivoPermiteConstruccion=true`.
- Unlike BREAK, the selection code does **not** copy the selected global BUILD `actionPos` into `objetivoAccionLocal`; that field is currently populated only for BREAK.
- The executor then runs a fresh local `NavPlanner.plan` toward the selected feet waypoint. That local plan is expected to rediscover and emit a BUILD node with its own `actionPos`.
- The BUILD actuator is downstream of an accepted local route. Its switch branch first requires a non-null `node.actionPos()`, then exact lease, empty placement cell, callback success, post-placement world verification, support/AABB validation, and feet approach.
- Therefore zero BUILD actuator events means the selected global BUILD waypoint did not reach an accepted/executed local BUILD route. It does **not** prove that the placement callback itself failed.

This may be intentional to allow local replanning, but it means the selected global BUILD edge is not actually carried into the local execution contract.
